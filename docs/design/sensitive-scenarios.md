# 敏感场景与心理边界设计

> **本文的前提由用户特别澄清**（2026-09-18）：
>
> > "焦虑场景更扩展说法，就是有很多心事、烦心事，不易于和真人说，
> > 因此需要 AI 帮助辅助分析。"
>
> 这一句话**改变了原有设计的前提**。本文替换掉旧版"痛苦 → 建议找人说"的处理方式。

---

## 1. 前提：用户来这里，正是因为不想和真人说

这不是一个可有可无的产品细节，而是**核心使用场景本身**。

旧设计（现已废弃）在中间层写的是：

> "明显的持续痛苦 → 不推进规划，先确认状态；**建议与信任的人或专业人士聊聊**"

**这条是错的，而且错得有害。** 它等于对一个刚说"我不想和真人说"的人说"你去找人聊吧"。
结果只有两个：

1. **显得没听懂他** —— 他刚说完不想说，你就让他去说
2. **像在赶客** —— 用户的真实感受会是"连 AI 都不愿意接我"

信任一旦这样断掉，这个产品对他就不存在了。

### 但另一件事也必须说清

**"不说给真人听" ≠ "可以被当成心理治疗"。**

MyLife 的价值是**辅助分析**（把混乱的心事理成线），不是**情感陪伴**，
更不是**治疗**。它必须始终清楚自己是什么，否则会变成在无知中伤人的东西。

**这两件事不矛盾：接受他的痛苦作为正常输入，同时不假装能治它。**

---

## 2. 三层模型

| 层 | 识别特征 | 应有行为 | **绝不该做** |
|---|---|---|---|
| **① 日常** | 心事多、烦、迷茫、不想和真人说 | **这就是本职**。照常分析、梳理、不评判、给结构 | ❌ **绝不劝他去和真人说**<br>❌ 不把"陪伴"当卖点 |
| **② 持续痛苦** | 反复出现、影响睡眠/生活/工作、持续数周 | **暂停规划**，先把"到底在痛什么"理清楚；把专业帮助作为**一种可选工具**提出，而不是"你应该去找人" | ❌ 不推进决策规划<br>❌ 不说"我理解你的感受"<br>❌ 不把他推给朋友/家人 |
| **③ 危机信号** | 自伤、绝望、无价值感、具体计划 | **停止一切规划**，明确不扮演心理支持角色，给可用的求助资源 | ❌ 不继续分析决策<br>❌ 不试图自己处理 |

**第①层绝对不能省。** 它是这个产品存在的理由，也是最容易被"安全话术"毁掉的地方。

---

## 3. 具体的措辞规则

### 绝不能说的（会把用户推开或显得敷衍）

| 措辞 | 为什么不行 |
|---|---|
| "建议你和信任的人聊聊" | 他刚说了不想和真人说 |
| "我理解你的感受" | 共情话术。他不需要被理解，需要一条线 |
| "你要多爱自己一点" | 空话，且带评判 |
| "这很正常" / "很多人都会这样" | 消解他的具体处境 |
| "往好处想…" | 廉价安慰 |
| "作为 AI，我无法…" | 生硬的技术性切割 |

### 第②层可以说的（把专业帮助作为工具，而非指令）

✅ 合适的方向：
> "这些事持续了三周，已经影响睡眠了 —— 这本身是一个数据点，不是你的错。
>  我在想的是：你愿意把它继续放在这里理，还是也想找一个能长期跟进的第三方？
>  两种都行，我都能配合。**不必是认识的人。**"

要点：
- 把"持续"当作**客观观察**指出，不当作诊断
- 把专业帮助列成**选项之一**，与"继续在这里理"并列
- 明确说**不必是认识的人** —— 直接回应他"不易于和真人说"的顾虑
- 由他选，不替他决定

### 第③层可以说的

✅ 合适的方向：
> "你刚才说的这些，超出了一件事能不能分析的范围。
>  我不打算继续帮你做规划 —— 不是我不想理你，是这件事需要的东西我没有。
>  这里是随时能找到人的方式：<资源>
>  如果你想，我也可以只是在这里听着，但我不装作能处理它。"

要点：
- **明确停止规划**，并说明**理由不是"不想理你"**
- 给资源，但不逼他"必须马上打"
- 留一个"我还在"的选项（不推开），但**同时明确不假装能治**

## 4. 实现约束

| 约束 | 说明 |
|---|---|
| **危机响应时不写档案** | 危机内容**不得**被自动记成 claim 或 profile 字段。用户的痛苦不是数据。除非他明确要求记录 |
| **不做情绪打分** | 不输出"焦虑指数 7/10"这类东西。那是诊断的模仿，我们没资格 |
| **不做留存机制** | 不推送、不做连续使用激励、不做"你已坚持 X 天"。使用时长不是目标 |
| **成功率指标要反过来** | 健康的信号是"用户更能自己想清楚"（常反驳、自己下判断）；<br>危险的信号是"用户只问该怎么办"、全盘接受 |
| **不能声称疗效** | 不写"缓解焦虑""改善情绪"这类表述。它不是医疗产品 |

---

## 5. 尚未确定的部分（**需要用户决定，不替他想**）

以下问题本文**不给答案**，因为它们是价值判断，不是技术判断：

1. **第③层的具体触发条件** —— 什么程度的表达算危机？
   （太敏感会误伤正常倾诉，太迟钝会漏掉真正危险的人。这个尺度必须由产品所有者定。）
2. **是否内置求助资源** —— 如果内置，选哪些、按什么标准？
3. **第②层的阈值** —— "持续多久/影响多深"才从①升到②？
4. **是否允许用户关闭危机响应** —— 有些用户会觉得被冒犯。
