# 证伪链：反证引擎的重新设计

> **状态：已实现并实测**（`src/lib/defeater.js` + `mylife_defeaters` 工具 + 32 个测试）。
>
> 起因：用真实语料测试时，词法极性反证引擎**完全失效**（23 条证据、0 findings）。
> 用户提出了更好的思路：**从关键点 A 找到反向的 D|E|F，再用 D|E|F 去搜索、判断、决策。**
> 本文是这个思路的形式化、实测与落地设计。

---

## 1. 为什么原引擎失败（实测证据）

原引擎（`src/lib/evidence.js` 的 `findTensions`）用**词法极性词典**：
在"去留/满意度/能力信心/财务安全感/意愿强度"五个轴上匹配正负词
（如 `想跳槽` vs `不会离开`），同轴极性相反且跨时点即判为张力。

**在真实语料上，它给出 0 findings。** 但人眼能看到至少三条明显张力：

| 张力 | 为什么词法抓不到 |
|---|---|
| "一定该离开" ↔ "愧对好领导" | **不在同一命题上**：一个是评价领导，一个是决定去留 |
| "同事领导都 nice" ↔ "每一天都不快乐" | **对象不同**：一个是**人**，一个是**系统** |
| "钱不排第一位" ↔ 最激烈情绪全在待遇 | 需要**跨主题聚合**，不是找反义词 |

**结论：反证的本质不是"找反义词"，是"找能推翻结论的东西"。**
于是改用证伪链。

---

## 2. 证伪链设计

```
主判断 P
   │
   ├─ 生成「什么能推翻 P」→ 证伪项 D1…Dn，分两类
   │     ├─ internal：这个人自己文中就有的张力
   │     │     · 对不同对象的相反评价（人好 / 系统烂）
   │     │     · 声明 vs 实际行为（说钱不重要 / 情绪全在待遇）
   │     │     · 承认的小事 vs 强烈反应
   │     └─ gap：若成立则 P 被推翻，而判定所需信息**本人能自答但没给**
   │
   ├─ 用每条 D 去检索（原文 / 证据图 / 后续接入语义检索）
   │
   └─ 判断三态之一：
         A 找到支持 D 的原话   → 主判断被削弱
         B 找到否定 D 的原话   → 主判断被加强
         C 原文无相关证据       → **空白本身就是结论**
```

**第三态是这套设计最关键的部分。**
传统反证只关心"找到反例了吗"；而 C 告诉我们
**"你的判断建立在一片没有数据的区域上"** —— 这往往比找到反例更有用。

---

## 3. 实测（2026-09-18，真实语料 12,683 中文字）

主判断 P = `我该离开这家公司`，用 `deepseek-chat`，**总耗时 9.5 秒**。

### 生成的证伪项（6 条）

| # | 类型 | 证伪项 | 判定 |
|---|---|---|---|
| 1 | internal | 感谢领导、A 绩效 ↔ 该离开 | ✅ 有支持 |
| 2 | internal | 爱财 ↔ 钱不排第一位 | ✅ 有支持 ⚠️ |
| 3 | internal | 曾相信美好 ↔ 不信向善 | ✅ 有支持 |
| 4 | gap | 其实仍热爱编程 | ⛔ 被否定 |
| 5 | gap | 领导认可足以弥补其他不满 | ⬜ 无证据 |
| 6 | gap | 对教育行业的热爱是否仍在 | ⬜ 无证据 |

### 关键结论

- **序号 1 与人工分析一致** —— 系统独立发现了"愧对好领导 vs 一定该离开"这条核心张力。
- **序号 3 是人工漏掉的** —— "曾相信美好" vs "不信向善"的**信念转变**，是真实的。
- **序号 5、6 正确识别出空白** —— 这正是"你握的是理由不是依据"的证据。
- **序号 2 是误报** ⚠️ —— 原文是**自我澄清**（"我爱财，但在工作上不把钱放第一"），
  不是矛盾。系统把它当成了张力。

### 与原引擎的对比

| | 词法极性引擎 | 证伪链 |
|---|---|---|
| 真实语料命中 | **0** | 2 条真张力 + 2 处空白 |
| 依赖固定词典 | 是（中文词法极难维护） | 否 |
| 能识别"空白" | ❌ | ✅ |
| 误报风险 | 低 | **存在（见序号 2）** |
| 成本 | 0（纯规则） | 每次约 10 秒 LLM 调用 |
| 可离线 | ✅ | ❌ 需 LLM |

**判定：证伪链更接近问题本质，应作为主路径；词法引擎退为"零成本的快速预筛"。**

## 4. 必须守住的约束（否则会变成指责）

第 2 条的误报说明了风险：**把"自我澄清"误判为"自相矛盾"，在心理场景下是有害的。**
用户在深夜写下这些，不是在等一个系统来指出他逻辑不严谨。

因此落地时必须强制：

1. **输出是提问，不是判定。**
   ❌ "你前后矛盾" → ✅ "这两句放在一起时，你自己怎么看？"
2. **必须给出"这两句可能同时为真"的解释路径。**
   （与现有 `renderRestoration` 的 `AXIS_BRIDGE` 同一原则）
3. **internal 型必须显式标注对立双方是什么** —— 让用户能自己判断是否是误解。
4. **允许用户否决**：每条证伪项都要能被用户标记为"这不是矛盾"，
   并记录下来，用于校准后续生成。
5. **gap 型的措辞要中性**："这一点在记录里没有依据"，
   而不是"你连这个都没想过"。

## 5. 落地形态（**已实现**）

```
src/lib/llm.js       薄 DeepSeek 适配器（不 import dsh 内部包）
src/lib/defeater.js
  generateDefeaters({ proposition, corpus, llm })   → D1…Dn（含 type/label）
  searchDefeaters({ defeaters, corpus, llm })        → 四态 A/B/R/C
  buildDefeaterAnalysis({ ... })                     → 分析 + 汇总
  renderDefeaterReport({ ... })                      → 提问式文案（纪律写进代码）

tools: mylife_defeaters({ proposition, corpus?, file? })
```

**依赖注入 `llm` 而非直接 import dsh 内部包** ——
与本插件"不依赖任何 dsh 包、任何布局下都能加载"的既有取舍一致。
调用方可传 `ctx.llm`，测试时可传 stub，**因此可以完整单测而不烧 API**。

### 测试策略（已按此实现）

- `generateDefeaters` / `searchDefeaters`：用 **stub llm** 测流程与四态分类
- `renderDefeaterReport`：测措辞纪律（不得出现指控性措辞、必须有提问、
  R 态不得说成"加强了主判断"）
- `mylife_defeaters` 工具：端到端（含语料自动加载、空语料报错）
- **真实 API 冒烟测试默认 skip**：`MYLIFE_LIVE_LLM=1 node --test test/defeater.test.js`

### 实现中修正的三个问题

真实语料第一版跑出来的结果暴露了三处，都已修并补了测试：

1. **证伪项写成长句散文** → 增加 `label`（≤24 字短标题），命题降为正文引用块
2. **"自我澄清"被判成"找到支持"** → 提示词明确：证伪项被自我澄清否定时判 `B`，
   并新增 `R` 态专门表示"本人已想过并排除"
3. **`gap` 问错了对象**（追问心理成因/传记） → 收窄定义：
   gap 必须是**能改变这个决定、本人当下就能给出答案的客观事实**
   （存款能撑几个月、市场定价、能否接受降薪）

另修一个渲染顺序 bug：`R` 态被 `type==='internal'` 分支抢走。
现在 verdict 与 type 是**两个独立决定**，互不遮蔽。

## 6. 顺带发现的安全问题

`~/.dsh/.credentials.yaml` 里的 API key 是**明文存储**
（`refs.DEEPSEEK_API_KEY: sk-…`，文件权限 0600）。

- 0600 权限是合理的，但**明文**意味着任何能读该文件的进程都能拿到密钥
- 我在调试时通过 `yaml.load` 读到了它 —— **说明"读这个文件"就等于"拿到密钥"**
- 建议：至少确认该文件不被任何同步盘（iCloud/Dropbox）覆盖；
  若担心，可改用环境变量注入。**这不是本插件的职责，但值得你知道。**
